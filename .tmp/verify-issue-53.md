# Issue #53 検証記録: セーブ画面で既存スロットを押すと確認なしに上書きされる

- ブランチ: `issue-53-saveconfirm`(`issue-54-savedate` から分岐)。再現に使ったビルドは `issue-30-publish`(f19fa50)の `html/build/dist`。`SaveDialog` / `UI.showConfirm` は #54 の変更の対象外で、どちらのビルドでも同じソース
- 確認日時: 2026-11-09 01:00〜01:10 JST
- ブラウザ: Playwright 1.61.1 同梱のヘッドレス Chromium(SwiftShader)、1280×800、新しいコンテキスト(セーブ無しの状態から)
- デスクトップ版: 未確認(ディスプレイが無く `:desktop:run` が起動しない。`.tmp/verify-desktop.md` 参照)

## ソース上の確認処理

- `SaveDialog.modifyButton()`: スロット行のクリックで `childrenPressed()`(自動保存・削除・名前変更のアイコン)を除外し、`ui.showConfirm("$text.overwrite", "$text.save.overwrite", () -> save(slot))` を呼ぶ。OK のあとにだけ `save(slot)` が走る
- `UI.showConfirm()`: Cancel / OK の 2 ボタン、Escape / Back で閉じる
- 自動保存: `Control` の既定値は `save-<n>-autosave = !gwt`。**ブラウザ版の既定はオフ**。定期自動保存(`Saves.update()`)と終了時保存(`PausedDialog.runExitSave()`)はスロットの自動保存がオンのときだけ動く

## Phase 1: 再現と切り分け(ブラウザ)

準備: プロトタイプ(ウェーブ)で、状態 A = ウェーブ 1 のままスロット「slotA」、ウェーブを 2 回進めた状態 B = ウェーブ 2 でスロット「slotB」を作った。どちらも行に `Autosave: Off` と出る(`verify-issue-53/01-two-slots-autosave-off.png`)。上書きの有無は localStorage `io.anuke.moment:save-0-datas` の先頭(保存時刻とウェーブ)で判定した。

| 操作(状態 B のまま) | 結果 |
|---|---|
| slotA の行(アイコンの外)を 1 回クリック | 確認ダイアログ「Are you sure you want to overwrite this save slot?」が出た(`02-confirm-shown-over-back.png`) |
| → Cancel | slotA は変わらない(保存時刻・ウェーブ 1 のまま) |
| slotA をクリック → Escape | 変わらない |
| slotA の行を間を置かずに 2 回クリック | 確認は 1 枚だけ出て、2 回目のクリックはモーダルに吸われた。上書きされない。OK はスロット行と離れた画面下部にあるので、連続クリックが OK に当たる配置ではない |
| slotA をクリック → 画面下の **セーブ画面の「Back」の文字の位置(655,754)をクリック** | **slotA がウェーブ 2 で上書きされ、セーブ画面も閉じた**(`03-click-back-label-overwrote.png`) |

最後の操作が報告の現象に当たる。確認ダイアログは出ているが、次の 2 点が重なって「確認なしに上書きされた」ように見える。

1. 確認ダイアログの背後が暗くならない(`.tmp/verify-desktop.md` の不具合 B1)。ポーズメニュー、セーブ画面、確認ダイアログの文字が重なって描かれ、確認ダイアログが出たことに気付きにくい
2. 確認ダイアログの OK(x≈647〜843, y≈735〜780)が、セーブ画面の Back(x≈525〜755, 同じ高さ)の右半分に重なる。「Back」の文字はちょうど OK の上にある。確認に気付かずに Back を押すと OK を押したことになり、`save(slot)` がセーブ画面を閉じるので、利用者には「Back で閉じたら上書きされていた」としか見えない

### 分類

計画の (a)〜(d) のどれにもそのまま当てはまらない。

- (a) 確認が出ない: 当たらない。確認は毎回出る
- (b) 連続クリックで OK が受理される: 当たらない。行の連続クリックは OK に届かない
- (c) 自動保存・終了時保存: 当たらない。ブラウザ版は自動保存の既定がオフで、両スロットともオフ
- (d) 再現しない: 「確認なしの上書き」としては再現しないが、利用者から見て同じ結果になる操作は上記のとおり再現する

最も近いのは (d) で、原因は確認処理ではなく、背景の減光が描かれないこと(B1)と、確認ダイアログの OK がセーブ画面の Back に重なる配置。

## Phase 2: 修正

**コードは変更していない。** 指示された修正は (a) の `SaveDialog.modifyButton()` と (b) の `UI.showConfirm` の OK 遅延有効化だけで、どちらも今回の原因に効かない(OK の遅延有効化は表示アニメーション後に Back の位置をクリックした場合を防げない)。原因に効く修正は次のどれかで、範囲と影響が #53 の想定と違うため、判断を利用者に残す。

- B1(`dialog` スタイルの `stageBackground: dialogDim` が描かれない)を直し、確認ダイアログの背後を暗くする。全ダイアログに効く
- 確認ダイアログのボタン位置、またはセーブ画面の Back の位置をずらし、重ならないようにする

## Phase 3: 回帰確認

コードを変更していないので、再ビルド後の再確認は行っていない。修正前の挙動として、Cancel / Escape で上書きされないこと、OK(Back の位置のクリックを含む)で上書きされることを上の表で確認した。上書きの判定は localStorage のメタデータで行い、ロードしたワールドでは確かめていない。
