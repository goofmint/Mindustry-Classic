# Issue #57 検証記録: 日本語の折り返し

## 概要
- 日時: 2026-11-09
- ブランチ: `issue-57-wrap`(`issue-55-console` から分岐)
- 結論: 日本語の説明文が文字の間で折り返されるようになった。CodeRabbit ブロックの詳細は「品質を1個ずつ / 2段階上げて」となり、「1 / 個ずつ」の分割はなくなった。プロトタイプのマップ説明でも小書きのカナや「ー」が行頭に来ない。英語の表示は変わらない
- 証跡: `.tmp/verify-issue-57/`(PNG 5 枚)。変更前の状態は `.tmp/verify-5.2/05-ja-levels-1280.png` と `06-ja-coderabbit-info-1280.png`

## 変更

### 文言側(`core/assets/bundles/bundle_ja.properties` のみ)
- 片側が数字(または `{0}` などのプレースホルダの括弧)で、もう片側が日本語の文字である半角スペースを削除した。57 行、107 か所
- 「(-2 か -1)」のように、負の数の前のスペースも同じ規則で詰めた(「(-2か-1)」)
- 英単語やマークアップの前後のスペース(`[accent]CodeRabbit[]`、`CI を`、`Android 4.4以前` の `Android` の後など)は残した。キーの追加と削除はない
- 新しい文字は足していないので、`tools/chars_ja.txt` とフォントは変えていない
- `python3 -I tools/check_bundles.py`: OK(en 581、除外 67、ja 514)

### 描画側
- `core/src/io/anuke/ucore/graphics/JapaneseFontData.java`(新規): `BitmapFontData` のサブクラス。`getWrapIndex` で、空白での折り返し位置(既存の処理)と日本語の折り返し位置のうち、あふれた文字に近い方を返す。日本語の折り返し位置の条件は次のとおり
  - 前後のどちらかが日本語の文字(ひらがな、カタカナ、CJK 記号と句読点、漢字、全角・半角形)
  - どちらも空白でない
  - 前の文字が ASCII の英数字でない(英単語や数字の途中で分けず、「1個」「CodeRabbitは」のように数字・英単語と後ろの日本語を同じ行に残す)
  - 前の文字が開き括弧(行末禁則)でない
  - 後の文字が行頭禁則文字でない(小書きのかな、ー、句読点、中点、？！、閉じ括弧、繰り返し記号。集合は `LINE_START_PROHIBITED` の 1 か所で定義)
  - 条件を満たす位置がなければ 0 を返し、`GlyphLayout` があふれた文字の直前で分割する(極端に狭い幅では禁則が破られる。クラスのコメントに記載)
  - 判定は `char` の範囲比較と `String.indexOf` だけで、GWT で使えない API は使っていない
- `UI.loadSkin()`: 日本語のときだけ、スキンの美咲フォント(`japanese`、`japanese-chat`)と同じ `.fnt`、ページ、markup 設定で `JapaneseFontData` のフォントを作り、既定フォントとして使う。スキンの美咲フォントはスキンに残り、テクスチャを持ち続ける。整数倍の拡大の処理は変えていない。英語のときの処理と `Label` は変えていない
- `JapaneseFontDataTest`(10 件): 日本語の判定、行頭禁則の判定、サンプル文字列での折り返し位置(「エージェント」→「ジェント」、「品質を1個ずつ」→「1個ずつ」、英単語、行末の開き括弧、英語は空白でだけ折り返すこと)

## 計画からの逸脱
- 計画は `Skin` のフォントローダーに `cjkWrap` を足す案だった。依頼の指示どおり `UI.loadSkin()` で美咲フォントにだけ使い、`Skin.java` と `uiskin.json` は変えていない
- 計画の規則(片側が日本語なら分けてよい)のままだと、「品質を1個ずつ」が「品質を1 / 個ずつ」と切れうる。Issue の「1 / 個ずつ」を確実に避けるため、ASCII 英数字の直後では分けない規則を足した
- 行末禁則(開き括弧)は計画になかったが、「(」や「「」が行末に残るのを避けるために足した
- `bundle.properties`(英語)は変えていない(依頼の指示)
