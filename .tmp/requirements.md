## 目的と対象

CodeRabbitの普及を目的に、AI SDLCを疑似体験できるブラウザゲームを、Mindustry Classicの改造で作る。

- 対象: エンジニアリングマネージャー、意思決定者
- 利用場面: イベントとSNSでの拡散
- 形式: ブラウザですぐ遊べる。既存のOSSを改造し、GPLで公開する
- 複雑さ: 求めない。気軽に触れて、CodeRabbitの価値が伝わること

土台は、Mindustry Classic(Anuken/Mindustry-Classic)。リポジトリを実際に取得して、コードを読んで確認した。

- ライセンス: GPL-3.0(LICENSEファイル)

- ビルド前提: JDK 8、Gradle 4.10.2、GWT 2.8.0、libGDX 1.9.8。ブラウザ版は、JavaをGWTでJavaScriptに変換して作る。完成したビルドは、リポジトリに入っていない

## ゲームの全体像

プレイヤーは、コードを生む設備と、品質を上げる施設をつないで流れを組み、納品したコードの得点で目標を目指す。納品したコードの品質が低いほど、敵が増える。

1. コード鉱脈の上に、コードを生む設備(人間のエンジニア、AIコーディングエージェント)を置く。未検証のコードが出る
2. パイプライン(コンベア)で運ぶ。PR(ルーター)がコードを溜めて、隣の施設に配る
3. 品質を上げる施設(レビュー、テスト、CI)を通す。順番は自由で、同じカテゴリの施設をもう一度通っても、品質は変わらない
4. コア(本番環境)に納品する。これがリリースにあたる。品質×重要度の得点が入る
5. 納品したコードの品質が低いほど、敵の数が増え、高いほど減る
6. 敵は、砲台などで迎え撃つ。コアが壊されるか、納品で残高が0を下回ると負け。残高が目標得点に届くと勝ち

品質に関わる施設は、シニアエンジニア、CodeRabbit(レビュー)、ユニットテスト、E2Eテスト(テスト)、Jenkins、GitHub Actions(CI)。トークン(電力)は、AI、CodeRabbit、テスト、CIの施設が消費する。

## コードのアイテム設計

コードは、品質7段階×通過状態8通り×重要度2種類の、112種類のアイテムで表す。1個ずつの値は持たせない。

- 品質の値: -5、-3、-2、-1、0.5、0.8、1の7つ。最大は1
- 出発点の品質: 人間のエンジニアは-2か-1。AIコーディングエージェントは、レベルで違う(初期は-5か-3、中間は-3か-1、最上位は-1だけ)。出るたびにランダム
- 通過状態: レビュー、テスト、CIの、それぞれ済か未かの組み合わせで8通り。同じカテゴリの施設を、もう一度通ることはできるが、品質は変わらない。もう一度通るときも、処理時間と、トークン(トークンを使う施設の場合)を使う
- 品質の上がり方: 施設を1つ通ると、品質が上がる。上がる段数は、施設ごとに設定できる。CodeRabbitは2段階上、ほかの5施設は1段階上
- 重要度: 2種類。値は1と2。コードを生む設備が、ランダムに出す
- 得点: 品質×重要度(掛け算)

* アイコン: 品質は色(-5が赤、1が青)、重要度は形(丸、星)、通過状態は右下のドット(テストが黒、レビューが白、CIが緑)で表す。実際に作られる組み合わせは70パターン。品質と重要度の14枚の基本画像に、ドットを重ねて、プログラムで作る

## 施設

施設の性能と費用は、施設ごとに違う。費用の数値は、未決定。

| 施設 | 役割 | トークン消費 | 備考 |
| --- | --- | --- | --- |
| 人間のエンジニア | コードを出す(品質-2か-1) | なし | 高くて遅い |
| AIコーディングエージェント | コードを出す(品質は、レベルで違う。初期は-5か-3、中間は-3か-1、最上位は-1だけ) | あり(コードを出すたび) | 安くて速い。3段階に強化できる |
| シニアエンジニア | レビュー | なし | 一定時間に1つ通す。並べて増やせる |
| CodeRabbit | レビュー + 迎撃 | あり | 1つのブロックで、レビュー変換と迎撃を兼ねる。迎撃はトークンで撃つ。品質が2段階上がる |
| ユニットテスト、E2Eテスト | テスト | あり |  |
| Jenkins、GitHub Actions | CI | あり |  |
| PR | 溜めて、隣の施設に配る | なし | ルーター。品質は変えない |
| 発電機 | 燃料をトークンに変える | なし | 5種類(ローカルGPU、オンプレミス、国内クラウド、海外クラウド、AIデータセンター)。燃料は、本家の発電機に従う |
| ポンプ、導管 | 液体をくみ上げて運ぶ | なし | 水、石油、溶岩の床から |

- 搬送: パイプライン(コンベア、通常、高速、超高速の3種類)、クロスポイント(ジャンクション)、バイパス(トンネル)、API連携(テレポーター)。ソーターは削る
- 防衛: 砲台12種類(弾薬は使わず、すべてトークンで撃つ)、AIによる自動修正(修復砲台、大型を含む2種類)、ファイアウォール(シールド発生器)、WAF(壁5種類: 石、鉄、チタン、鋼の大型、チタンの大型。ドア2種類、シールド壁)。鋼の壁、ディリウムの壁、ディリウムの大型壁は使わない
- トークン: 電力の呼び名。発電機で作り、配線で届ける。人間のエンジニアとシニアエンジニアは使わない
- 液体: 水、石油、溶岩の3種類。石油はvGPU、溶岩はdGPUという燃料の名前を持つ。水は、AIデータセンターの冷却水

* 燃料の入手(iGPU、PCIe): iGPUの在庫の床、PCIeの在庫の床に、調達設備(本家の石炭ドリルを「家電屋」、ウランドリルを「ベンダー」と呼ぶ。この2つだけを使う)を置いて仕入れる。マップには、コード鉱脈に加えて、この2種類の床も描く

* マップ: 256×256を3枚。コード鉱脈は、本家の鉄鉱石の床(画像とマップの色c3a490)をそのまま使う。iGPUとPCIeの在庫の床は、当面、本家の画像(石炭鉱石、ウラン鉱石)のまま。鉱石の自動生成(oreGen)を使う。使わないチタン鉱石も出るが、掘る設備を使わないので、見た目だけになる

- 費用の決め方: 本家の建設費の、資源の個数の合計を、得点の値にする。新しい施設は、役割の近い本家のブロックの費用を借りる。遊びながら調整する

## 目標・得点・建設費

納品したコードの得点は、残高として貯まり、設備の建設費に使う。残高が目標得点に届くとクリアで、納品で残高が0を下回るか、コアが壊されると負け。

- 1個あたりの得点: 品質×重要度。品質は最低-5、最大1
- 残高: 納品で増減する。建設に使うと減る
- クリア: 残高が、目標得点に届く
- 負け: コアが壊される。または、納品で残高が0を下回る
- 初期の手元資金: 150。遊びながら調整する
- 敵への影響: 納品したコードの品質が低いほど、敵の数にかける倍率が上がり、高いほど下がる
- 予算: 設けない。トークンの源泉は、発電機(燃料は液体に限らない)

* 調整する値: 目標得点、敵の倍率の式、敵の出現位置の数、コアの位置は、現状のコードの値で始め、遊びながら調整する
